# BAB II. DESKRIPSI SINGKAT MASALAH / KEBUTUHAN YANG TERIDENTIFIKASI

## 1. Latar Belakang Masalah/Pekerjaan

Kegiatan pameran dan festival kuliner di Bandung sering diikuti oleh berbagai tenant retail dan F&B. Mitra tempat survey Kerja Praktik ini melibatkan tiga tenant yang rutin mengikuti event, yaitu Papyrus Photo (jasa studio foto dan photobooth), Let’s Go Gelato (dessert gelato), dan Terve Factory (cokelat artisan) (Tan et al., 2024).

Berdasarkan hasil survei dan wawancara dengan IT Manager (Bapak Muhamad Rijal Abdulatif), proses pencatatan transaksi di lokasi event saat ini masih menghadapi beberapa kendala:

1. **Pencatatan Masih Manual:** Setiap tenant masih mencatat transaksi secara manual di buku nota atau spreadsheet terpisah. Saat pengunjung ramai, hal ini menyebabkan antrean pembayaran menjadi panjang (Sourav & Emanuel, 2021).
2. **Data Penjualan Tidak Terintegrasi:** Manajemen dan penyelenggara event kesulitan melihat total omzet dan stok produk secara real-time karena laporan baru direkap secara manual setelah event selesai (Sentosa & Ramadhan, 2025).
3. **Risiko Selisih Uang Kasir:** Perhitungan kasir pada saat tutup shift sering mengalami ketidakcocokan antara uang fisik dan catatan transaksi akibat kesalahan rekapitulasi manual (Wicaksono et al., 2024).
4. **Koneksi Internet Event Tidak Stabil:** Lokasi event sering mengalami kendala sinyal internet. Aplikasi kasir berbasis web murni rentan terganggu jika koneksi terputus. Oleh karena itu, dibutuhkan aplikasi mobile dengan basis data lokal (SQLite) agar kasir tetap bisa melayani transaksi tanpa internet (*offline-first*) (Lestariningati, 2018).
5. **Risiko Pembatalan Nota Tanpa Izin:** Pembatalan transaksi lunas (void) yang dilakukan manual rentan dimanipulasi. Sistem memerlukan pengamanan verifikasi kode OTP Admin 6 digit untuk setiap pembatalan nota (Abdullah et al., 2019).
6. **Pencetakan Struk Lambat:** Pencatatan resi tulis tangan dinilai kurang praktis. Kasir membutuhkan aplikasi yang terhubung ke printer thermal Bluetooth.

Untuk mengatasi permasalahan di atas, penulis merancang dan membangun **Aplikasi Point of Sale (POS) untuk Pengelolaan Transaksi Event** berbasis Web dan Mobile Android.

## 2. Rumusan Masalah/Pekerjaan

Berdasarkan latar belakang di atas, rumusan masalah dalam Kerja Praktik ini adalah:

1. Bagaimana merancang dan membangun aplikasi POS terintegrasi berbasis Web Admin (Laravel 11) dan Mobile Kasir (React Native) untuk pengelolaan transaksi event (Sentosa & Ramadhan, 2025)?
2. Bagaimana menerapkan arsitektur offline-first menggunakan SQLite pada Mobile Kasir agar transaksi tetap berjalan saat jaringan internet terputus (Lestariningati, 2018)?
3. Bagaimana merancang fitur keamanan pembatalan nota lunas (void) dengan otorisasi OTP Admin 6 digit dan pencatatan audit log (Abdullah et al., 2019)?
4. Bagaimana merancang manajemen shift kasir (opening/closing shift) dengan penutupan kasir yang akurat?
5. Bagaimana merancang dashboard KPI dan laporan keuangan dengan 8 filter yang dapat diekspor ke PDF dan Excel (Wicaksono et al., 2024)?

## 3. Batasan Masalah/Pekerjaan

Ruang lingkup pekerjaan Kerja Praktik ini dibatasi pada hal-hal berikut:

Modul utama mencakup: Master Data (Pegawai, Cabang, Kategori, Menu, Harga Cabang, Sales Mode, Promosi, Metode Bayar), Shift Management, Transaksi POS, Pembayaran Cash & Manual Non-Cash (input nomor referensi EDC/transfer), Void Nota OTP Admin, Offline Sync, Audit Log, serta Dashboard & Laporan Keuangan 8 Filter (PDF/Excel).

## 7. Gambaran/Deskripsi Umum Sistem/Aplikasi dalam KP

Aplikasi Point of Sale (POS) untuk Pengelolaan Transaksi Event dirancang sebagai platform berbasis web (Web Admin) dan mobile (Mobile Kasir) yang dapat diakses oleh beberapa jenis pengguna sesuai dengan hak akses masing-masing, yaitu Admin/Supervisor, Staf Kasir Lapangan, dan Manajemen/Penyelenggara Event (Tan et al., 2024).

Rencana fungsi dan fitur utama yang akan dibangun adalah sebagai berikut:

1. **Modul Master Data & Promosi:** pencatatan data pegawai/kasir, cabang/tenant (Papyrus Photo, Let's Go Gelato, Terve Factory), kategori, menu, harga cabang regional, sales mode, promosi dinamis, dan metode pembayaran.
2. **Modul Shift Kasir & Offline Sync:** pengelolaan sesi buka/tutup shift kasir, input modal awal, rekonsiliasi kasir (*silent shift closing*), dan sinkronisasi otomatis transaksi offline (SQLite) ke basis data pusat.
3. **Modul Transaksi POS & Pembayaran:** pemrosesan pesanan pada layar POS, pembayaran tunai/manual non-tunai (EDC/QRIS/Transfer), cetak struk thermal via printer Bluetooth, dan pengamanan pembatalan nota lunas (*void*) berbasis OTP Admin 6 digit.
4. **Modul Dashboard & Laporan:** menampilkan ringkasan kinerja penjualan event dalam bentuk grafik (omzet, tren penjualan 7 hari, produk terlaris) serta menyediakan fitur cetak/ekspor laporan otomatis dalam format PDF/Excel dengan 8 kombinasi filter.

Gambaran alur sistem secara umum dapat digambarkan sebagai berikut: kasir di lokasi event melayani transaksi penjualan dan menginput data melalui aplikasi Mobile Kasir, kemudian data tersebut tersimpan pada basis data lokal SQLite dan disinkronkan ke basis data terpusat (MySQL) server Web Admin. Selanjutnya, sistem akan mengolah seluruh data transaksi tersebut menjadi informasi dalam bentuk dashboard KPI dan laporan keuangan yang dapat diakses langsung oleh pihak manajemen/admin kapan saja, tanpa perlu menunggu proses rekap manual dari masing-masing booth tenant.

# BAB III. Daftar Literatur

## 1. Metode RPL yang Akan Digunakan Selama Kerja Praktik

Metode rekayasa perangkat lunak yang direncanakan digunakan dalam pengembangan sistem ini adalah metode Waterfall, dengan tahapan analisis kebutuhan, desain sistem, implementasi (coding), pengujian (testing), dan pemeliharaan (Sourav & Emanuel, 2021). Pemilihan metode ini didasarkan pada ruang lingkup Kerja Praktik yang relatif terbatas dan kebutuhan sistem yang sudah cukup jelas sejak awal. Pengujian sistem pada tahapan akhir menggunakan teknik pengujian fungsionalitas *black-box testing* (Wicaksono et al., 2024).

## 2. Teori Terkait Tahapan Metode RPL dan Alat Bantu Pendukung

Pada setiap tahapan metode Waterfall akan digunakan beberapa alat bantu (tools) pendukung, di antaranya diagram UML (use case diagram, activity diagram, class diagram, dan sequence diagram) untuk tahap desain, serta Entity Relationship Diagram (ERD) untuk perancangan basis data relasional (Febrianti et al., 2021).

## 3. Teori Tentang Domain Aplikasi/Pekerjaan KP

Domain aplikasi pada Kerja Praktik ini berkaitan dengan sistem informasi manajemen (Management Information System) dan Point of Sale (POS), yaitu sistem yang digunakan untuk mendukung proses pengumpulan, pengolahan, penyimpanan, dan penyajian data guna membantu pengambilan keputusan manajerial, khususnya pada aspek pengelolaan transaksi penjualan, stok produk, dan laporan keuangan event (Sentosa & Ramadhan, 2025). Aplikasi mobile kasir dirancang dengan keandalan pemrosesan data lokal (Lestariningati, 2018) dan otorisasi keamanan pembatalan nota berbasis OTP (Abdullah et al., 2019).
